# Milestone v0.9.5: Kay Brand Renaming

**Status:** ✅ SHIPPED 2026-05-16
**Phases:** 8-10
**Total Plans:** 3

## Overview

This milestone completed the Kay brand migration sweep. The work renamed
first-party docs and copy to Kay, migrated Kay-owned runtime paths and tooling
where safe, and audited compatibility boundaries so legacy names remain only
where they are required.

## Phases

### Phase 8: Kay-first docs and copy sweep

**Goal**: Rewrite user-facing docs, help text, README content, and UI copy to
Kay-first language, and keep the rename inventory aligned with the actual
exceptions.

**Depends on**: Nothing
**Plans**: 1 plan

Plans:

- [x] 08-01: Rename docs, help text, and README copy to Kay-first language

**Details:**
User-facing docs and help text were rewritten to present Kay as the primary
brand, the docs landing page now links the policy and inventory, and the rename
inventory captures the remaining compatibility exceptions.

### Phase 9: Runtime paths, scripts, and binary renames

**Goal**: Migrate Kay-owned scripts, binaries, workspace paths, and release
plumbing to Kay naming while preserving existing launch and build workflows.

**Depends on**: Phase 8
**Plans**: 1 plan

Plans:

- [x] 09-01: Rename Kay-owned runtime paths and tooling with compatibility aliases

**Details:**
Kay-first build and release entrypoints now lead the runtime path, the justfile
prefers Kay names with compatibility wrappers, and the remaining runtime docs
call out the legacy names as explicit compatibility boundaries.

### Phase 10: Boundary audit and validation

**Goal**: Audit protocol, schema, generated, and package identifiers; then
verify the rename migration with build and targeted regression checks.

**Depends on**: Phase 9
**Plans**: 1 plan

Plans:

- [x] 10-01: Audit boundary tokens and verify the rename migration

**Details:**
The remaining compatibility-bound names were classified in the rename
inventory, Kay-first docs were confirmed for the remaining config and runtime
surfaces, and the migration was validated with `./build-fast.sh` plus targeted
regression checks.

## Milestone Summary

**Key Decisions:**

- Kay-first branding is the default for first-party surfaces.
- Legacy names remain only where compatibility or upstream comparison requires
  them.
- Rename decisions are tracked in a living inventory.
- Daily upstream reconciliation is part of the migration process.

**Issues Resolved:**

- Completed the docs-first Kay branding sweep.
- Completed the runtime-path, script, and binary naming changes.
- Audited and documented the remaining boundary exceptions.
- Verified the migration with the required build and targeted regressions.

**Issues Deferred:**

- Compatibility aliases remain intentionally in place until a versioned rename
  path is introduced for the remaining external contracts.

**Technical Debt Incurred:**

- Some package identifiers, generated protocol names, and legacy environment
  aliases remain as deliberate compatibility boundaries.
