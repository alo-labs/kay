# Milestone v0.9.6: Kay Home Isolation

**Status:** ✅ SHIPPED 2026-05-16
**Phases:** 11-11
**Total Plans:** 1

## Overview

This milestone made `KAY_HOME` the canonical isolated root for Kay-owned
writable state, session storage, and provider credential storage while
preserving the current default behavior when `KAY_HOME` is unset.

## Phases

### Phase 11: KAY_HOME root isolation foundation

**Goal**: Move Kay-owned writable state onto the resolved `KAY_HOME` tree and
make the runtime and tests use `KAY_HOME` as the only isolation root needed
for test/session storage.
**Depends on**: Nothing
**Plans**: 1 plan

Plans:

- [x] 11-01: Root writable state, session storage, and provider credentials under `KAY_HOME`

**Details:**
This phase centralized the Kay home resolution path, moved writable runtime
state such as auth, history, skills, worktree/session registry, and debug logs
under the resolved `KAY_HOME` tree, and updated the test harnesses so they can
run with `KAY_HOME` alone.

## Milestone Summary

**Key Decisions:**

- `KAY_HOME` is the canonical isolated root for Kay-owned writable state when
  it is set.
- When `KAY_HOME` is unset, Kay uses its normal default home layout.
- Session, transcript, auth, skills, worktree, and debug-log paths resolve
  under the resolved Kay home tree.
- Tests exercise `KAY_HOME` directly and no longer rely on caller-managed
  home redirection.

**Issues Resolved:**

- Completed the `KAY_HOME` isolation foundation for Kay-owned writable state.
- Routed MiniMax credential lookup through the Kay home tree.
- Updated live provider and notes-app tests to isolate on `KAY_HOME` alone.
- Passed the required build and pre-release gates for the milestone.

**Issues Deferred:**

- The broader `codex` / `code` naming cleanup continues as a separate
  migration stream.

**Technical Debt Incurred:**

- A read-only upstream mirror and several historical package or protocol names
  remain outside the scope of the `KAY_HOME` isolation milestone.
