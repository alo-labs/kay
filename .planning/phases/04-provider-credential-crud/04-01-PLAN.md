<threat_model>
## Trust Boundaries

- CLI arguments and shell history are untrusted paths for secret input.
- Pasted TUI text is untrusted until it is validated and persisted.
- `auth.json` is the only on-disk credential store this phase should mutate for provider API keys.
- Logging, tail notices, and feedback banners must never print raw provider secrets.

## STRIDE Register

| threat_id | category | component | disposition | mitigation_plan |
|---|---|---|---|---|
| PM-01 | information_disclosure | `code-rs/cli/src/main.rs`, `code-rs/cli/src/login.rs` | mitigate | Make `--api-key` the explicit direct-argument path, keep `--with-api-key` as the stdin path, and never echo the raw key in help text, logs, or errors. Document the shell-history / process-list risk clearly. |
| PM-02 | information_disclosure | `code-rs/tui/src/bottom_pane/provider_credentials_view.rs`, `code-rs/core/src/auth.rs` | mitigate | Route all provider CRUD writes through the existing auth helpers, persist only in `auth.json.provider_credentials`, and redact key values in UI feedback and test output. |
| PM-03 | tampering | `code-rs/core/src/model_provider_info.rs` | mitigate | Keep provider ordering data-driven and explicit so `/provider` always shows OpenCode Go, MiniMax, then OpenAI, rather than inheriting an unstable map iteration order. |
</threat_model>
