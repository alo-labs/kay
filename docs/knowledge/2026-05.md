# Knowledge - 2026-05

## Architecture Patterns

- Silver Bullet init for a brownfield repo should preserve existing instructions and docs, then layer new enforcement artifacts alongside them.
- GSD on this machine needs a shared runtime catalog in both `~/.claude/sdk/shared/` and `~/.kay/sdk/shared/` to satisfy the local compatibility shim.
- Phase 1 stays cleaner when it is interface-first and leaves docs, live validation, and release work for later phases.
- Built-in provider registration and wire-slug normalization should move together so the active provider id and outbound request shape stay aligned.
- Kay slash-command renames should update the TUI enum, the formatter, and the user-facing docs together; otherwise the UI can show Kay while the prompt-expanding path still remains inconsistent underneath.
- Live acceptance repos used for Kay should be cloned from a trusted git checkout with a clean HEAD baseline; otherwise a local working tree can leak into the model's test context.
- Model-family prompt adaptations are the right seam for model-specific agent behavior fixes when the provider wire format is already correct; MiMo now adds a synthesis checkpoint without changing OpenCode Go transport behavior.
- OpenCode Go live streams need a shorter idle timeout than the generic provider default so a silent provider-side stall retries within Kay's live validation window.
- MiMo prompts should avoid the full skills catalog unless a task explicitly needs skills; large discoverability blocks can crowd out simple file-inspection behavior.
- Direct Xiaomi MiMo support can reuse the OpenAI-compatible chat transport and MiMo model-family profile, but it still needs separate provider credentials, picker visibility, and live acceptance coverage because the provider id is different from OpenCode Go.

## Known Gotchas

- `gsd-sdk` can fail if the higher-level wrapper package is missing a Node dependency, even when `gsd-tools` is still usable locally.
- `docs/` may already contain a mature documentation set; init should add canonical placeholders without deleting the existing docs tree.
- The docs-scheme gate can still block completion if the governed docs were not refreshed in the same session, even when the main task is otherwise done.
- Reserving a new built-in provider id can break custom config and rollout replay if the reserved-name guard and migration story are not updated together.
- The docs-scheme ledger has to list every governed doc key, not just the files touched by the main feature change, or the completion hook will keep blocking the task.
- The final Kay slash-command review needed a second docs-scheme refresh pass so the checklist timestamp and the governed docs landed in the same session.
- For live test fixtures, SB session markers under both `.claude` and `.Codex` need to agree with the current session or the docs gate keeps reporting stale coverage.
- OpenCode Go model families can need behavior guidance even when request routing and response-model metadata match; treat repeated file rereads and missing synthesis as an instruction-profile issue before changing provider plumbing.
- A clean single live pass is not enough for model-behavior fixes; the full release gate can still expose nondeterministic stalls that require transport-level retry tuning.
- If a model stalls before the first tool call, inspect the assembled prompt size and sections; behavior may improve by reducing optional instruction catalogs rather than adding more guidance.

## Key Decisions

- Keep the repo's existing Rust build gate as the completion check.
- Use the brownfield-safe, non-destructive path for all init scaffolding.
- Keep the OpenCode Go milestone's first phase foundation-only and modular.
- Reserve `opencode-go` as a built-in provider id and keep login guidance plus resume compatibility aligned with that choice.
- Treat `/kay` as the canonical prompt-expanding slash command for the UI and formatter path.
- Use trusted `git clone --no-local` for seeded live E2E repos so the model sees a reproducible baseline and not the source checkout's working tree.
- Keep MiMo anti-loop guidance scoped to the MiMo model family so stronger OpenCode Go families do not inherit unnecessary behavioral constraints.
- Keep OpenCode Go idle-retry tuning at the provider boundary, not per test, so real users benefit from the same recovery path as the live gate.
- Keep MiMo context dieting scoped to optional skills discovery so AGENTS.md and project-specific safety instructions still apply.
- Treat Xiaomi as its own provider namespace (`xiaomi/<model>`) even when the model names overlap with OpenCode Go's MiMo slugs.
