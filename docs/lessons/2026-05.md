# Lessons - 2026-05

## practice:init

- When a workflow depends on a generated cache file, restore the compatibility shim first and verify the CLI before touching the project.
- For brownfield init, write the durable project state early so later steps can build on concrete context instead of re-deriving it.
- When the docs gate complains about stale coverage, reconcile the checklist and the governed docs together instead of trying to clear the hook with only one side of the contract.

## practice:docs

- Preserve existing docs and add the new governance files alongside them.
- Keep monthly files short and append-only so they remain easy to scan.
- When provider registration changes, update the login copy, provider-reservation guard, and any resume-wire notes in the same session.
- If a task changes the docs-scheme expectations, refresh `docs/task-doc-checklist.json` with every governed doc key, then only mark a file `updated` if it was actually modified in the same session.
- If the gate still reports stale docs after the first pass, refresh the checklist and every named governed doc together again in the same session before re-running the gate.
- When Silver Bullet complains about a missing session marker, align the `.claude` and `.Codex` marker files to the current session before assuming the docs themselves are the problem.
- For live provider-model E2E repos, a trusted clean clone is more important than cloning "locally"; the wrong clone mode can leak uncommitted source changes into the model context.
- For model-behavior fixes, document the root-cause pattern in knowledge docs even when the production change is only a prompt/profile adjustment.
- For shared model families such as MiMo, keep provider-independent response and tool-use guidance in the family profile, then prove each provider namespace with live tests that inspect real file diffs instead of relying on model-reported JSON alone.
- When validating structured output on tool-backed model runs, require parseable contracted JSON but keep file-diff assertions as the source of truth; schema pressure alone can make some chat models answer before using tools.
- When a model family repeatedly produces a recoverable malformed tool-call shape, such as concatenated tool argument JSON or command strings where argv arrays are expected, fix it in the shared tool-call normalization path and keep provider-specific code limited to credentials, routing, and model registration.
- Treat first-token idle behavior as provider transport configuration, not model-family behavior, unless multiple providers for the same model show the same timeout profile.
- For JS live-edit harnesses, validate semantic reachability of generated functions in addition to syntax; a nested function can pass `node --check` while breaking event handlers.
- For model families that use shell-driven patching, combine prompt guidance with deterministic normalization for malformed-but-recoverable patch syntax; prompts alone may not prevent repeated malformed hunk headers.
- For weaker patching models, add an explicit fallback after repeated context mismatches; otherwise the model can burn the whole turn retrying semantically identical hunks.
- For schema-constrained model families that sometimes emit progress prose, validate the final assistant message before turn completion and feed a repair developer message instead of accepting a non-contract last message.
- When a live harness checks generated UI behavior, keep assertions semantic enough to accept equivalent local variable names such as `typing` and `isTyping` while still rejecting missing guards.
- When a release preflight has both deterministic and live phases, strip live opt-in credentials from the deterministic phase and let the explicit live gate own provider traffic.
- When one provider namespace exposes a model-family transport incompatibility, encode the compatibility switch at the model-family layer and cover both provider namespaces in tests; do not special-case only the provider that happened to fail first.
- Treat model-stream retry events as status, not process failure, once the core successfully recovers and emits a final task completion; keep non-retry errors fatal for automation.
- For curated live release gates, extend the per-turn budget when the model is still in Kay's normal retry path; do not remove a slow model from the matrix just to make the gate faster.

## practice:planning

- Keep phase 1 foundation-only and interface-first; docs/live/release work belongs in later phases unless the scope explicitly changes.
- If the docs-scheme gate flags stale files, refresh the governed docs and the checklist in the same session.
- For bugfixes against agent stalling, write the regression around the model-family contract first; it keeps the fix narrow and avoids speculative orchestration changes.
